# AC → scenario coverage

One row per acceptance criterion from issue #880 (as revised with the owner), and per risk the
architect's design surfaced. Every row resolves to ✅ Covered or ⚠️ Excluded with a reason.

Capability is `profiling` throughout; scenario names are given as
`Requirement → Scenario`.

| Risk | `--retention` and `--loop` are validated independently but interact: a window shorter than the shipping delay prunes every chunk before it can ship, and nothing is reported as failing. Reachable with `--loop 1h` against the DEFAULT retention | `Desired profiling state is stored on each node → A retention window shorter than the shipping delay is refused` | ✅ Covered — the check is relational, names both flags, and shares one grace constant between the CLI and the node |
| Risk | A slow Pyroscope puts a pass past the reconcile unit's start timeout, systemd kills it, and nothing it learned is persisted — so the last-success timestamp reports a stale value while shipping partly works, and the report reads as a dead reconciler | `Completed JFR chunks are shipped to Pyroscope → One pass does not run past its systemd timeout` | ✅ Covered — shipping is bounded per pass and reported as truncated in its own right, and an EXIT/TERM trap persists counters, metrics and effective state, pinned in the bash tier by signalling a live pass |

| Risk | Auto-pruning must never delete operator-dropped artifacts (heap dumps, jstacks) from the 777 `artifacts/` directory | `Local JFR retention is bounded → Operator-supplied artifacts are never pruned` | ✅ Covered |

| Risk | A profiler that will not attach must not render identically to one deliberately stopped | `Profiling state is inspectable → A failing attach is distinguished from a deliberate stop`; `→ A node that has not reconciled yet is reported as unknown` | ✅ Covered — desired and attached are reported separately and a typed `Profiling.AttachFailed` is emitted |

| Risk | A detach that failed must not be recorded as a clean stop, or the reconciler stops converging | `Changing profiling arguments switches the session without losing data → A session that will not stop is not replaced or misreported` | ✅ Covered |

| Risk | An empty argument list ("profile with the profiler's own defaults", reachable over MCP) must not be read as "no session record" | `The reconciler makes actual profiling state match desired state → A session started with no arguments is recognised as converged` | ✅ Covered — otherwise every pass detaches and re-attaches to a live database JVM, losing samples and resetting the reported session age |

| Risk | "Profiling enabled, nothing attached" converges silently, so a node dead for hours is indistinguishable from a healthy one in both the log store and the metric store | `The reconciler makes actual profiling state match desired state → Wanting to profile with nothing to attach to is reported`; `→ Desired and attached state are separable in the metric store` | ✅ Covered — the no-process path logs and increments `edl_jfr_attach_skipped_total`, kept apart from `edl_jfr_attach_failures_total` because a stopped database and a refused jattach are fixed in different places, and `edl_jfr_profiling_desired`/`edl_jfr_session_attached` make "wanted but dead" a query rather than an SSH session |
| Risk | Attaching to a database that has not finished starting KILLS it: async-profiler attaches with jattach, jattach signals `SIGQUIT`, and a process that has not installed a handler for it yet takes that signal's default disposition — terminate and dump core. Observed on a live 3-node cluster: db1 died 17s into its own startup (`code=dumped, status=3/QUIT`) in the same second the reconciler logged `jfr_attach_failed ... "Process 5419 not found"`, and db2 never started. Likely rather than unlucky, because passes run every 60s and a database takes longer than that to become ready | `The reconciler makes actual profiling state match desired state → A database that is not ready to be attached to is never signalled`; `→ Waiting for the database is reported as a wait, not as a failure`; `→ A deferred attach does not stop the rest of the pass`; `→ A deferred pass does not discard a session it cannot ask about`; `→ Readiness does not depend on where the database binds`; `Profiling state is inspectable → A node waiting for its database is reported as waiting` | ✅ Covered as *prevention* — no asprof call of any kind (`start`, `stop`, `status`, `metrics`) is made until `cassandra-ready` finds the native transport listening, with a ten-minute process-uptime backstop so a deliberately disabled native transport does not disable profiling forever. The probe reads the socket table rather than connecting to an assumed address: the native transport binds to `rpc_address`, the node's private IP, so a loopback connect answers "closed" on every healthy node and every node falls through to the backstop, which is exactly what a first attempt at this probe did on a live cluster. The bash tier stubs `asprof`, so the kill itself is out of its reach and the tests pin the decision instead: a pass against a not-ready pid invokes no asprof at all, logs `jfr_attach_deferred`, counts `edl_jfr_attach_deferred_total`, leaves `edl_jfr_attach_failures_total` at zero, and still ships and prunes. The probe's own answers are asserted directly against a port nothing is listening on, a listener bound to a **non-loopback** address (the only configuration these nodes run, and the one a loopback connect cannot see), and the uptime backstop; the fixture asserts its own premise, failing loudly if the listener turns out to be reachable on loopback and could therefore pass against the bug. |
